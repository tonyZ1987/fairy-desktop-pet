## 2. 动画参数（**全部来自官方源码，不是我调的**）

### 2.1 眼睛分层呼吸 —— 这是它"活"的关键
`mascot-style.js` 给四层各自挂了 `dsh-fairy-pulse-*`，**周期 0.72 s、`alternate`**（即完整往复 1.44 s），
并**按由外向内依次滞后**：

| 层 | 元素 | scale | 相位滞后 |
|---|---|---|---|
| 外 | `.dsh-fairy-sclera`（眼白＋光晕＋接触描边） | **0.985 → 0.91** | 0 ms |
| 3 | `.dsh-fairy-layer-three`（`#9daee0` r=33） | **1.00 → 0.90** | **−45 ms** |
| 2 | `.dsh-fairy-layer-two`（白环 24.15 + 虹膜 `#317bcf` 23.5 **＋高光球**） | **1.00 → 0.87** | **−90 ms** |
| 1 | `.dsh-fairy-layer-one`（细白环 16.6 + 瞳孔 16） | **1.00 → 0.85** | **−180 ms** |

缓动：`cubic-bezier(.72, 0, .28, 1)`，相位走三角波（`readEyeProgress`）。
→ **外层几乎不动、内层抖动更大、且内层落后** ⇒ 眼睛像在"呼吸/凝视"，而不是整体缩放。
**v1 完全没做这个，只做了整体缩放 —— 这就是"动画不顺滑/死板"的根因。**

### 2.2 睫毛旋转
```css
.dsh-fairy-corners { animation: dsh-fairy-lashes calc(15s / rate) linear infinite;
                     transform-origin: 80px 80px; }
@keyframes dsh-fairy-lashes { to { transform: rotate(360deg); } }
```
**15 秒一圈、线性、无限**；`rate` 由设置项 `dsh-fairy-mascot-animation-speed` 控制。
形状本身 = **深色圆 r=51.75 ∪ 方 86×86(rx 2) 再旋 3°**，`#2b3388`，裁到 r<67。
因为方的**边长(±43) < 圆(51.75)**，所以只有**四个角**露出来 ⇒ 视觉上是"四根睫毛/眼睑"在扫。
> 注：4 重对称 ⇒ 视觉周期 ≈ 3.75 s；15 s 是"方"本身转一整圈的时间。

### 2.3 `thinking`（半睁眼）—— 官方实现
```css
[data-state="thinking"] .dsh-fairy-eye { clip-path: url(#dsh-fairy-thinking-eye-clip); }
.dsh-fairy-thinking-clip-shape { transform-origin: 80px 60px; animation: dsh-fairy-thinking-clip .72s ... infinite alternate; }
```
clipPath：`<path d="M20 60 Q80 90 140 60 V160 H20 Z"/>` ＋ `<rect x="0" y="108" width="160" height="52"/>`
每帧变换：`translateY(14.5 + p)`、`scaleY(0.55 + 0.45·p)`，`p` 随主时钟往复。
→ 眼睑是**一段向下压的贝塞尔弧**，把眼白上部裁掉，露出下方白色月牙（高光球留在月牙里）。
**与视频实拍 t=50 s 逐像素吻合**（见 `TEST_G`）。

### 2.4 眼睛随机闪烁（**已按主人要求加入**）

官方 `scheduleEyeFlicker()` + `@keyframes dsh-fairy-eye-flicker-overlay`：

| 项 | 官方值 |
|---|---|
| 触发间隔 | **随机 1750–3600 ms**（÷ `animationRate`） |
| 单次时长 | **随机 155–255 ms** |
| 图层 | 一个**白色圆**，半径 `outerVisibleEdge = 68.6`（只盖住盘与"睫毛"），`pointer-events:none` |
| 不透明度关键帧 | `0% → 0`；`22% → 随机 0.026–0.048`；`48% → 随机 0.006–0.016`；`72% → 随机 0.018–0.040`；`100% → 0` |
| 缓动 | `cubic-bezier(.32, 0, .68, 1)`，每个关键帧区间各自套一次 |

**关键认知：它极淡——最高只有 4.8% 不透明度、持续不到 0.2 秒。** 单个事件肉眼几乎察觉不到，
但累计起来就是"这东西是活的"。所以我还出了一张 **`STEP2_闪烁检查条.png`**：

## 3. 睁 ↔ 半睁 的衔接（**已按主人反馈重做**）

### 3.1 第一版为什么生硬
第一版是"**在没有眼睑 / 有半睁眼睑 两张遮罩之间做交叉淡入淡出**"。
那本质上是**化开**（上半只眼渐渐消失），不是**眼睑压下来**——所以观感生硬、发虚。

### 3.2 现在：单一连续弧，眼睑几何下落
改成**一条连续可调的眼睑弧**，形状与官方 `thinking` clipPath 同源
（二次贝塞尔，两端点 y=A、控制点 y=B=A+sag，中点 `(A+B)/2`），
用一个 `open_t ∈ [1,0]` 参数把整条弧**从眼白上方（y≈22，完全不遮）平移到半睁位置
（y≈87，随呼吸微动）**：

```
mid_think = 15·sy + 60 + ty      # 官方 thinking 弧中点（含 translateY / scaleY）
sag       = 30·sy                # 垂度随 sy 缩放，保持官方弧形
mid       = 22 + (mid_think - 22)·(1 - open_t)
A = mid - sag/2 ;  B = mid + sag/2
```

| 项 | 第一版 | 现在 |
|---|---|---|
| 过渡机制 | 两张遮罩交叉淡入淡出（"化开"） | **单一弧几何下落（"眼睑压下来"）** |
| 眼睑边缘 | 硬阈值的 0/1 遮罩 | **1.6 user unit 羽化**（≈2.8 px @280，边缘柔和） |
| 闭眼时长/缓动 | 0.30 s smoothstep | **0.70 s smoothstep**（对称 ease-in-out） |
| 睁眼时长/缓动 | 0.30 s smoothstep | **0.55 s smoothstep**（比闭略快） |

**缓动为什么用 smoothstep 而不是官方那条 `cubic-bezier(.72,0,.28,1)`**：
实测那条曲线前 27% 的行程几乎为零，之后才快速落下 —— 会读成"**顿一下再掉下来**"，同样生硬。
smoothstep（对称 ease-in-out）没有这个死区，是"衔接变化"最平顺的通用选择。

### 3.3 与官方的差异（请主人裁定）
| 项 | 官方 | 本步做法 |
|---|---|---|
| 切换 | **硬切**（`data-state` 一变 clip 立刻套上） | 连续弧 + 0.70/0.55 s 缓动过渡 |
| 眼睑边缘 | SVG clip 的硬边（浏览器抗锯齿） | 1.6 unit 主动羽化 |

要严格 100% 复刻官方硬切：把 `step2_make_video.py` 顶部 `T_CLOSE`/`T_OPEN` 两个区间改成零长度即可。
过渡时长/缓动集中在 `open_t_at()` 一个函数里，改一处即可。

## 4. ⚠️ 必须知道的性能事实（决定第③步怎么写主程序）

本渲染器**逐帧全量重算**（280 px 显示、2× 超采样 ⇒ 560² 像素 × 约 50 次 numpy 逐元素运算）：
> **实测 0.47 秒 / 帧**（720 帧耗时 330 s）

**离 60 fps（16.7 ms/帧）差 28 倍**，现在这个写法**不可能做实时桌宠**。

**第③步主程序必须改成"图层预栅格化 + 每帧只做合成"**：
1. 启动时把每个图层各自渲成一张 RGBA 小图（外盘／睫毛／眼白＋光晕／layer3／layer2／layer1／高光球），一次成本；
2. 每帧只做：各层按自己的 scale **缩放**（PIL `resize`／仿射）+ 合成（PIL `alpha_composite`）；
3. 睫毛层**只按角度旋转**，不重画；
4. 眼睑 clip 预先算成 24 档灰度遮罩，插值取用。
预计可降到 **1–3 ms/帧**，60 fps 有余量。

## 7. 定稿（2026-09-21 16:5x）：三个动效 + 三处修正

### 7.1 眼睑落位后的变动幅度 —— **按视频实拍量出来，原实现大了约 3.6 倍**

从 mp4 的工作态片段（t=99~103.5s，30fps）逐帧量眼睑下沿 y：

| | 实测 |
|---|---|
| 眼睑下沿 y 范围 | 254.0 – 259.0 px |
| **峰峰** | **5.0 px** |
| 换算 | ≈ 眼白高度的 **3.5%** ≈ **3.4 user unit** |

原实现摆 **12 unit**（12.5%）⇒ 过大 3.6 倍。
⇒ 结论：**总峰峰锁在 3.3 unit**，不靠放大幅度来体现"动感"。

### 7.1b 眼睑落位与浮动的最终定稿（2026-09-21 17:3x）

### 7.2 "最外圈特效"缺失 —— **补齐外发光**

### 7.3 首尾帧衔接生硬 —— **改为严格无缝循环**

**原理**：让两个周期在循环长度上整数倍闭合。

| 周期 | 值 |
|---|---|
| 睫毛**视觉**周期 | 15 s ÷ 4 = **3.75 s**（方是 90° 对称，转 90° 与转 0° 完全同形） |
| 眼睛呼吸周期 | 官方 1.44 s → **循环片改用 1.5 s**（差 4.2%，肉眼不可辨） |
| **循环长度** | **7.5 s = 2 × 3.75 = 5 × 1.5** ⇒ 两周期同时闭合 |

⇒ 第 450 帧与第 0 帧**数学上同一姿态**。

**实测校验**：`STEP2_接缝校验_常态.png` / `_工作态.png`
——第 0 帧、第 449 帧并排 + 差异 ×12。**接缝平均差 0.066 / 255（常态）、0.056 / 255（工作态）**，
差异图几乎全黑（只剩 1px 边缘痕）。闪烁事件也排在 `[0.45s, L-0.45s]` 内，不跨越接缝。
